Design notes

Why it looks like this

Live numbers first

The top of the page shows what the network is doing right now: connections against the limit, swarms, torrents, speeds. Every limit below has a number to compare against.

Where a setting lives

Each setting carries a small label: isol-core (swarms, signalling, RTC), WebTorrent (a real client or torrent option, named in mono), or Isol (a rule the app enforces on top). It keeps the design honest about what's built in.

Block unknown peers

Swarms find peers through the trackers but only connect on purpose, so blocking is cheap: unknown keys are seen and ignored. Torrent peers have no identity, so file sharing isn't affected; the setting says so.

The relay

WebRTC uses STUN to find a direct route. A TURN relay carries the data when a direct route fails, and "Always use the relay" hides your IP address from peers at the cost of speed.

Three kinds of files

Everything else, files you made (Priority), and files you keep for the network (Important: kept threads, synced boards). Each has its own peers, speeds, upload slots and seeding rule, and the global speed limit still caps the total.

Apply, then reconnect

Network changes need swarms and torrents to reconnect, so they don't apply on every keystroke. A bar at the bottom counts changes and applies them together.
